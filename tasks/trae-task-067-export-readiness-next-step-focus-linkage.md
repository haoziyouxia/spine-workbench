# trae-task-067-export-readiness-next-step-focus-linkage

## 任务概述
在 066 已经补上"下一步该做什么"动作引导的基础上，继续把动作引导和下方实际问题区做强联动，让用户点击后不只是展开，还能更快看到对应内容，减少"按钮按了但还得自己找"的落差。

## 任务目标
1. 优化下一步引导按钮与对应问题分组之间的定位联动
2. 让阻塞态、警告态点击后更容易直接看到首要处理区
3. 保持轻量，不引入复杂导航系统或全局浮层
4. 不改动既有导出准备度主结构，只做可见性和操作闭环增强

## 实现要求
1. 阻塞态点击"展开查看并修复"后，除展开外，应尽量让用户直接看到关键阻塞区
2. 警告态点击"展开查看建议"后，应尽量让用户直接看到建议优化区
3. 若页面已有 sticky 区或摘要区，联动时注意避免被遮挡或定位落差太大
4. 交互要与 057、058、059、062、063、064、065、066 保持一致，不做大改
5. 保持轻量自然，不新增复杂步骤条、复杂锚点系统、复杂筛选器

## 明确不要做
- 新页面
- 全局向导
- 复杂多区域跳转系统
- 与导出准备度无关的大改

## 验收标准
- 用户点击下一步动作后，能更快看到对应处理区域
- 阻塞态和警告态的引导闭环更完整，不只是"展开了"
- 不依赖复杂流程设计，也能明显减少寻找成本
- 整体仍然轻量、自然、稳定

## 实现方案

### 核心思路
为下一步引导按钮添加点击后的滚动定位功能，让用户点击后能自动滚动到对应的问题区域。

### 实现方法
1. 使用 React 的 `useRef` 为各个问题分组区域创建引用
2. 在点击下一步引导按钮时，除了展开分组，还自动滚动到对应区域
3. 添加平滑滚动动画，提升用户体验
4. 确保滚动位置考虑 sticky 区域的高度，避免内容被遮挡

### 具体实现
- 为 critical、recommended、optional 三个分组区域添加 ref
- 在 `handleNextStepAction` 中添加滚动逻辑
- 使用 `scrollIntoView` API 实现平滑滚动
- 考虑 sticky 头部的偏移量

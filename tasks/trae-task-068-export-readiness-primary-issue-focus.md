# trae-task-068-export-readiness-primary-issue-focus

## 任务概述
在 067 已经补上"点击动作后更快看到对应区域"的联动基础上，继续减少用户进入问题区后的判断成本，让用户一眼知道"当前最先处理哪一项"，而不只是看到一整个分组。

## 任务目标
1. 在导出准备度问题区中强化"首要问题"或"第一优先项"的可见性
2. 让阻塞态下用户进入问题区后更容易立即理解先修哪条
3. 若当前没有阻塞、只有建议项，则让用户也能快速识别最值得先看的建议
4. 保持轻量，不引入复杂排序面板或流程系统

## 实现要求
1. 优先复用现有校验结果和现有问题列表结构，不推翻当前布局
2. 可以用首项强调、轻量标签、简短提示文案等方式实现，但不要做复杂系统
3. 阻塞态下的"第一优先项"要足够显眼，但不要制造过强噪音
4. 警告态下也要保持克制，强调"建议先看什么"而不是制造阻塞感
5. 继续与 057-067 的导出准备度交互逻辑保持一致

## 明确不要做
- 新页面
- 复杂优先级后台配置
- 多步骤向导
- 与导出准备度无关的大改

## 验收标准
- 用户进入问题区后，能更快识别当前最先处理的项
- 阻塞态与警告态都能减少"展开后还要自己判断顺序"的成本
- 整体仍然轻量、自然，不演变成复杂工作流

## 实现方案

### 核心思路
在问题列表的第一项添加"首要处理"标签和视觉强调，让用户一眼就能识别出最先需要处理的问题。

### 实现方法
1. 在第一个问题项前添加"首先处理"标签
2. 为第一项添加特殊样式（边框高亮、背景强调）
3. 添加简短提示文案说明为什么这是首要处理项
4. 根据状态（阻塞态/警告态）使用不同的标签样式

### 具体实现
- 在 critical 分组的第一项添加"首要阻塞项"标签
- 在 recommended 分组的第一项添加"优先建议"标签
- 添加轻量视觉强调（边框、背景色变化）
- 添加简短提示说明处理优先级

3. `tasks/trae-task-068-export-readiness-primary-issue-focus.md` - 任务文件

2. 创建有错误的项目，验证阻塞问题的第一项显示"首要处理"标签和强调样式
3. 创建无错误但有警告的项目，验证建议项的第一项显示"优先建议"标签
4. 验证视觉效果足够显眼但不过度干扰
5. 验证与 057-067 的交互逻辑保持一致

1. 在问题列表的第一项添加明确的优先级标签
2. 添加轻量视觉强调，帮助用户更快识别首要处理项
3. 减少用户"展开后还要自己判断顺序"的成本
4. 保持轻量实现，不引入复杂系统

# trae-task-066-export-readiness-next-step-guidance

## 任务概述
在 065 已经完成关键摘要收敛与噪音控制的基础上，继续优化导出准备度区域中"下一步该做什么"的动作引导，让用户不只看到状态，还能更自然地理解接下来应该先看哪里、先处理什么。

## 任务目标
1. 优化关键摘要或状态卡片附近的下一步提示表达
2. 让阻塞态、警告态、就绪态各自都有更贴合当前状态的轻量引导
3. 优先让用户知道"先展开哪里 / 先处理什么 / 当前是否可以继续导出"
4. 保持轻量，不做复杂流程向导或多步骤系统

## 实现要求
1. 动作引导要贴近当前状态，不要泛泛而谈
2. 如果当前有阻塞问题，优先告诉用户先看阻塞项
3. 如果当前只有建议优化项，优先提示用户可继续查看建议项而不是制造紧张感
4. 如果当前完全就绪，要清楚提示当前可以继续导出
5. 保持与 057、058、059、062、063、064、065 的导出准备度交互逻辑一致
6. 不要引入复杂评分系统、复杂工作流面板、复杂筛选器、复杂设置系统

## 明确不要做
- 独立新页面
- 新的多步骤向导
- 自动修复系统
- 与导出准备度无关的大改

## 验收标准
- 用户看到当前状态后，能立即理解下一步该看哪里或做什么
- 阻塞态、警告态、就绪态的引导表达更自然、更贴合实际
- 不依赖复杂流程设计，也能提升处理效率
- 保持轻量自然，不演变成复杂系统

## 实现方案

### 状态检测函数
- `getNextStepGuidance()` 根据当前状态返回对应的引导信息：
  - **阻塞态**：标题"先处理阻塞问题"，描述"当前有阻塞问题需要修复才能导出"，按钮"展开查看并修复"
  - **警告态**：标题"建议查看优化项"，描述"当前可以导出，但建议先查看这些建议"，按钮"展开查看建议"
  - **就绪态**：标题"准备就绪"，描述"所有检查已通过，可以直接导出"，按钮"立即导出"

### 动作处理函数
- `handleNextStepAction()` 根据当前状态执行对应操作：
  - 阻塞态/警告态：展开相关问题组
  - 就绪态：直接触发导出

### UI 样式
- 添加 `next-step-guidance` 组件，包含图标、标题、描述和操作按钮
- 三种状态使用不同的配色方案：
  - 阻塞态：红色主题（#f76579）
  - 警告态：黄色主题（#ffd93d）
  - 就绪态：绿色主题（#4ecdc4）

### 验证方法

2. 创建无错误但有警告的项目，验证警告态引导显示正确（黄色主题，建议查看优化项）
3. 创建无错误无警告的项目，验证就绪态引导显示正确（绿色主题，提示可以导出）
4. 点击各状态的操作按钮，验证正确执行对应动作

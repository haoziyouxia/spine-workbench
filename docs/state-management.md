# State Management - Spine Workbench v1

## 1. 目标
让第一版在不引入过重复杂度的前提下，保持界面状态、项目数据和流程步骤一致。

## 2. 原则
- 状态尽量简单
- 一个项目只有一个当前活动草稿
- UI 状态和项目数据状态分开
- 优先可读和可维护，不追求花哨

## 3. 建议拆分

### Project State
保存业务数据：
- 当前项目信息
- 原图路径
- parts
- bones
- notes
- 当前项目状态

### UI State
保存界面状态：
- 当前选中的步骤
- 当前选中的 part
- 当前选中的 bone
- 画布缩放值
- 画布平移值
- 面板展开/折叠状态

## 4. 第一版建议
如果使用 React：
- 先用 Context + useReducer 或轻量 store
- 不急着上复杂全局状态方案

## 5. 状态更新原则
- 导入图片后更新 Project State 和当前步骤
- 修改部件后只更新 parts 相关数据
- 修改骨点后只更新 bones 相关数据
- 导出成功后更新项目状态为 exported

## 6. 需要预留的能力
- 保存草稿
- 重载草稿
- 后续加撤销/重做

## 7. 第一版先不做
- 多项目同时编辑
- 云同步
- 团队协同状态
- 复杂权限系统
